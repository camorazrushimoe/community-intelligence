# Community Intelligence — спецификация архитектуры

> Сервис сбора и структурирования «голоса игроков» для market intelligence рынка видеоигр.

## 1. Идея и позиционирование

Собираем мнения игроков из открытых сообществ и превращаем их в структурированный,
временной граф инсайтов. Клиент получает ответ не «сколько продалось», а
«почему злятся / чего хотят / что растёт».

- **Клиенты:** игровые студии (live-service, инди), паблишеры, инвесторы, UA/маркетинг-агентства.
- **Отстройка от конкурентов (Newzoo, Sensor Tower):** те работают с продажами/выручкой,
  мы — с голосом игроков (community signal).
- **Agent-native:** данные отдаются и человеку (дашборд), и ИИ-агенту (структурированный граф / API).

## 2. Архитектура — две части

```
[ Коллекторы ]  →  [ Хранилище и обработка ]
  (ingestion)        (Postgres + Neo4j + API)
```

### Часть A — Коллекторы (ingestion layer)

Отдельный сервис на каждый источник. Единый контракт: на вход — расписание/триггер,
на выход — нормализованные сигналы.

| Коллектор | Источник | Что тянет | Статус |
|---|---|---|---|
| `collector-steam` | Steam store API + appreviews | каталог игры, отзывы | MVP |
| `collector-reddit` | Arctic Shift API | посты/комментарии с упоминанием игр | MVP |
| `collector-discord` | (позже) | сообщения в сообществах | roadmap |
| `collector-steamdb` | (позже) | онлайн-игроки (concurrent) | roadmap |

### Часть B — Хранилище и обработка

Две базы, как задумано:

1. **База данных (Postgres)** — справочники + сырые/нормализованные сигналы.
   - `games` (Level 1), `signals` (Level 2), справочники топиков/источников.
2. **База графов (Neo4j)** — сущности + рёбра + временные ряды (Level 3).

Пайплайн:
```
collector → нормализация → Postgres → ETL → Neo4j → API / дашборд
```

## 3. Модель данных — 3 уровня

### Level 1 — Каталог игр (Postgres, таблица `games`)

Стабильный каркас, на который навешиваются все сигналы.

| Поле | Тип | Назначение |
|---|---|---|
| `steam_app_id` | int, PK | **первичный ключ** — мостик между Reddit и Steam |
| `name` | text | каноническое имя |
| `name_variants` | text[] | синонимы для матчинга: «CS:GO», «csgo», «Counter-Strike» |
| `genres` | text[] | жанры |
| `tags` | text[] | Steam-теги (для корреляций) |
| `developer` | text | |
| `publisher` | text | |
| `release_date` | date | отличать «хайп до релиза» от «пострелиз» |
| `price` | numeric | позже — связь цены и сентимента |
| `platforms` | text[] | PC / console / mobile |

### Level 2 — Сигналы (Postgres, таблица `signals`)

Единица голоса игрока: один пост / отзыв / комментарий.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | uuid, PK | |
| `source` | enum | `reddit` \| `steam_review` |
| `source_id` | text | id в исходнике |
| `source_url` | text | для верификации |
| `game_ref` | int, FK→games | **связка с каталогом** |
| `author` | text | |
| `timestamp` | timestamptz | для временного ряда |
| `text_raw` | text | исходник |
| `text_clean` | text | очищенный |
| `sentiment` | real | −1…+1 |
| `topics` | text[] | gameplay, bugs, performance, monetization, story, ui… |
| `score` | int | upvotes / helpful votes (вес сигнала) |
| `lang` | text | |

### Level 3 — Инсайты (Neo4j, граф)

- **Узлы:** `Game`, `Topic`, `Source`, `Author`, `Event` (патч/релиз), `Day` (временной срез).
- **Рёбра:**
  - `(Game)-[HAS_SIGNAL {sentiment, at}]->(Signal)`
  - `(Signal)-[ABOUT {sentiment}]->(Topic)`
  - `(Game)-[SENTIMENT_AT {score}]->(Day)` — временной ряд
  - `(Game)-[COMPETES_WITH]->(Game)` — позже, конкурентные связи

Первые агрегации:
1. **Game × Day × sentiment** — тренд настроения.
2. **Game × Topic × sentiment** — на что именно жалуются.
3. **Topic × Day** — растущие темы (тренд-детекция).

## 4. Ключ-связка (матчинг)

Связываем упоминание в Reddit с игрой через `steam_app_id` + `name_variants`.
Без каталога невозможно связать отзыв в Steam с обсуждением в Reddit.

## 5. Tech stack (рекомендация)

- **Postgres** (+ TimescaleDB опционально для временных рядов).
- **Neo4j** для графа (на старте можно pgRouting, но Neo4j проще для сущностей/рёбер).
- **Python + FastAPI** — коллекторы и API.
- **LLM (DeepSeek)** — извлечение топиков, сентимент, генерация синонимов.
- **Очередь** (опционально): NATS/Redis.

## 6. MVP scope

- 10–20 игр одного жанра.
- 2 коллектора: Steam + Reddit.
- Postgres (`games` + `signals`).
- Простейшая агрегация: **сентимент-тренд за 30 дней + топ-5 тем болей** по игре.
- Минимальный API (JSON), опционально простой дашборд.

## 7. Дорожная карта

1. **CI-1** Каталог игр (схема Postgres + матчинг имён).
2. **CI-2** Collector Steam (отзывы + метаданные).
3. **CI-3** Collector Reddit (Arctic Shift, поиск упоминаний).
4. **CI-4** Обработка сигналов (LLM: топики + сентимент).
5. **CI-5** Граф Neo4j (узлы/рёбра, временной ряд).
6. **CI-6** API/дашборд MVP (тренд + топ-5 болей).
